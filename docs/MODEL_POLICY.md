# AI 모델 사용 기준

2026-11-11 사용자 확정, 2026-11-15 노력 수준·운영 점검 추가(사용자 승인). 명세서 30장(Codex GPT-6.1 SOL Medium/High 기준)을 Claude 개발에 맞게 대응시킨 정책이다.

| 명세서 등급 | 작업 | Claude 모델 | 노력 수준 |
|---|---|---|---|
| Medium (탐색) | 파일·사용처 찾기, 단일 파일 요약, 로그·자료 추출 | Haiku 계열 작업자(scout·extractor) | low |
| Medium (기계적) | 이름 변경, 정해진 패턴 적용, 설정값 변경 | Sonnet 계열 작업자(mechanic) | low |
| Medium | UI·CSS, 문서, 기존 예시를 따르는 테스트·E2E, 빌드·배포 스크립트, 릴리스 노트 | Sonnet 계열 작업자(builder) | medium |
| High | 정밀 기하·충돌, 자동 배치 탐색, 저장 트랜잭션·복구, 스키마 마이그레이션, 복합 상태 오류, 고위험 구조 변경, 기준본 대조 설계·판정 | 메인 세션(Opus) | high |
| 상한 | 최상위 모델(Fable 계열) | 기본 사용하지 않음. 대형 독립 리뷰가 필요할 때만 사용자 동의 후 사용 | high |

- 작업자 노력 수준은 각 작업자 정의에 고정되어 있다. 메인 세션 노력 수준은 사용자의 채팅 설정을 따르며, AI가 스스로 확인·변경할 수 없으므로 보고 시 "설정값 미확인"으로 적는다.

## 판단 기준
실수했을 때 테스트가 바로 잡아내는 작업은 Sonnet에 맡긴다. 테스트를 통과하면서 특정 경계값에서만 데이터가 틀릴 수 있는 작업은 Opus가 맡는다.
"직접 하는 편이 빠르다"는 이유만으로 Medium 작업을 Opus가 하지 않는다. 지시서 작성이 작업 자체보다 길어지는 아주 작은 수정(수십 줄 이하)만 예외로 하고, PR 본문에 사유를 적는다.

## 운영
- Sonnet 결과가 검사에서 실패하면 Opus가 이어받는다(재시도 1회).
- Phase 3(CAD)처럼 상호작용이 까다로운 영역은 Sonnet 구현 + Opus 검토.
- 기준본과 문자열 단위로 대조하는 화면 코드는 Opus가 대조 사례·기대값·수용 기준을 먼저 정하고, Sonnet이 구현, Opus가 대조 결과를 판정한다.
- 탐색: 한 질문에 직접 검색·읽기가 3회를 넘으면 Haiku 작업자에게 넘긴다.
- 기준본 저장소의 `tools/ai-task.cjs`(Codex SOL 라우팅)는 Codex 병행 사용을 위해 기준본에 그대로 둔다.

## PR 보고 의무
모든 PR 본문에 아래 형식의 "모델 배분" 절을 둔다. 사용자가 준수 여부를 확인하는 근거다.

```
## 모델 배분

```
