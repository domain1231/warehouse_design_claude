## Warehouse Layout Designer v2.5.0-alpha.17 (시험판 · pre-release)

alpha.16 이후 **Track E E3·E4·E5·E6·E7**과 배치 백업 한도 결함 수정(D-092)을 반영한 시험판입니다. 지표 산식과 배치 계산은 바뀌지 않았습니다. 프로젝트 데이터 스키마 **2.3.6** 호환은 그대로입니다.

### 저장 파일이 더 작아집니다 (E5 · E6)
- 배치 백업과 자동 배치 확인 이력 안에 반복해 들어 있던 스냅샷·배치를, 저장할 때 같은 내용의 기준일 스냅샷 참조로 줄여 씁니다. 앱 안 동작(복원·검증)은 그대로입니다.
- **v2.4.1·이전 시험판에서도 열 수 있습니다.** 다만 이전 앱에서는 참조가 든 배치 백업의 복원만 전체 취소됩니다(배치 변화 없음).
- 이전 앱에서 백업 복원까지 써야 하면 **저장소 관리 → JSON 저장 형식 → '기준본 호환 JSON'**으로 저장하세요(이전 읽기 쉬운 JSON과 같은 원문).

### 이력 정리 (E4)
- **저장소 관리 → 이력 정리**: 항목별 저장 크기 표, 배치별 최근 기준일 N개(기본 10)만 남기는 정리, 명령 이력 비우기(선택), 정리 미리보기.
- 현재 BEFORE·AFTER 배치, 각 배치의 최신 Excel 기준일, 재고 이력, 가져오기 기록은 지우지 않습니다.
- 정리 전 프로젝트 백업을 자동으로 만들고, **실행 취소(Ctrl+Z)**로 되돌릴 수 있습니다.

### 오류 문구 (E3)
- 파일이 너무 크면 종류·실제 크기·상한·해결 방법을 함께 보여줍니다. 예: `프로젝트 JSON 25.1MB(탐색기 24,512KB) · 상한 24MB(탐색기 23,438KB) 초과 — …`
- 크기는 MB와 Windows 탐색기 '크기' 열의 KB를 함께 표시합니다. 프로젝트 JSON·ZIP, 참고 도면 이미지, 재고 CSV, Excel·CSV에 적용됩니다.

### 결함 수정 — Excel 가져오기 '백업 용량 한도 초과' (D-092)
- 기준일 이력이 쌓이면(운영 규모로 약 7회째 가져오기부터) Excel 가져오기·BEFORE→AFTER 복제·백업 복원이 '백업 용량 한도 초과'로 실패하던 문제를 고쳤습니다. 저장되는 백업 합계는 여전히 3.2MB 이하입니다.

### 크기 예산 검사 (E7)
- 가상 사용 시나리오(가져오기 30·배치 저장 30·자동 배치 10)의 크기를 CI에서 잽니다. 기준일이 많이 쌓이면 파일이 커지므로(기준일당 약 0.4MB), 수십 회 가져온 뒤에는 **이력 정리**를 권장합니다.

### 확인 부탁
- `warehouse_project_v2_3_6_2026-11-25.json` 불러오기 → `JSON 백업`(작은 JSON) 저장 크기(로드맵 예상 약 4MB 안팎) → 다시 불러오기 → 비교 화면 결론 문장 동일.
- 저장소 관리 → 이력 정리 미리보기 표, 정리 실행 후 Ctrl+Z.
- 배치 백업 복원(가져오기 이력의 '이전 상태 복원').
- Windows Edge에서 위 항목.
