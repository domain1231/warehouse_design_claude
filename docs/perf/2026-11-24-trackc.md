## 원인과 수정
- 랙 선택마다 오른쪽·상단 공간 지표를 다시 그리며 Track C 공간 구성(랙 > 보관 불가 > 통로 > 잔여 누적 합집합)과 기존 metrics의 면적 합집합을 두 시나리오에서 계산한다. 내용 기준 LRU 캐시(`AREA_CACHE`)가 16칸이라 한 번 그리기에 필요한 키 수(시나리오당 약 6개 × 2 + 기존 3개)를 넘어 계속 밀려났다(캐시 thrash).
- `AREA_CACHE_MAX` 16 → 64. 캐시 키는 도형 내용이라 제자리 수정에도 오래된 값을 돌려주지 않는다(단위 검사 `tests/unit/metrics-cache.test.js`). 계산 값 변화 없음, 골든 불변.
- 끌기·확대·저장은 수정 전후 차이가 측정 편차 범위.

## 추가: 공간 지표 메모(perf/select-memo)
- `src/ui/panels.js`에서 `scenarioSpace`·`scenarioDelta`·`shelfWeightedVolume`·`aisleSettingIssues`를 입력(배치 객체 동일성 + referenceArea·aisleRules·높이 정책 값)이 같으면 직전 결과를 재사용. 세션의 편집·적용·실행취소는 모두 structuredClone 후 확정하므로 바뀐 배치는 항상 새 객체이고, 선택만 바뀐 그리기는 같은 객체를 쓴다. 끌기 미리보기 중에는 패널을 그리지 않는다.
- 500랙, 조용한 상태 3회: 랙 선택 48.6 / 54.6 / 52.0ms(수정 전 55~65, Track C 전 45), 라벨 전환 199 / 205 / 194ms, 끌기 44~50, 확대 29, 저장 338~502(1회 튐).
- 남은 선택 비용은 도면 다시 그리기(renderPlan)와 기존 metrics()의 면적 합집합(편집 후 캐시 미스)이다.
