# 성능 비교 — v2.4.1 vs v2.5.0-alpha.2 (2026-11-16)

- 도구: 세션 작업 공간의 Playwright 측정 스크립트(저장소 미포함), Linux Chrome, 1600×1000, 오프라인, 각 1회 측정.
- 랙 수 56(예시 Excel 규모)·200·500개의 가상 배치. 1000개는 시간 제한으로 제외(이전 측정에서 끌기 121→64ms).
- 단위 ms(heap은 MB). 1회 측정이라 ±20% 안팎의 차이는 오차일 수 있다.

## 해석
- 선택·끌기·첫 화면·메모리는 모든 규모에서 재구축이 빠르거나 작다(끌기 500랙 143→37ms, 선택 421→57ms).
- 배치 불러오기는 비슷하다(±10%).
- **라벨 방식 전환 500랙은 재구축이 느리다(355→459ms).** 실제 창고 규모(56랙)에서는 79→42ms로 빠르므로 당장 문제는 아니지만, 큰 창고를 위해 라벨 다시 그리기 최적화 후보로 남긴다.

## 정정 (2026-11-20)
- 위 표의 '라벨 방식 전환 500랙'은 두 앱에서 **서로 다른 방식**을 비교한 값이었다. 측정 도구가 선택 목록의 앞 4개 방식을 돌렸는데, 재구축에는 '랙 번호 + 높이 활용률'(D-039)이 끼어 있어 순서가 달랐다.
- 같은 방식끼리 다시 재면(500랙, 3회 반복 중앙값, 측정 편차 큼) 재구축이 모두 빠르거나 비슷하다: 실제 적재율 272→239ms, 상세 345→251ms, 최소 234→104ms. 높이 활용률 방식은 재구축에만 있음(약 250ms).
- 같은 날 화면을 다시 그릴 때 반복되던 합집합 면적 계산(`unionArea`)에 최근 결과 기억을 넣었다(결과 동일, 단위 검사 추가).
